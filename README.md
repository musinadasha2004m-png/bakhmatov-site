# Сайт Сергея Бахматова

Статический сайт: чистый HTML/CSS/JS, без сборки. Можно открыть `index.html`
прямо в браузере или задеплоить на GitHub Pages / Netlify / Vercel — подойдёт
любой обычный хостинг статики.

## Структура

```
index.html              — главная страница (лендинг)
login.html               — вход в закрытый раздел марафона
marathon.html             — список дней марафона
day.html                   — страница одного дня (?d=1 … ?d=30)
assets/css/style.css        — все стили, цвета — через CSS-переменные в :root
assets/js/auth.js             — простая клиентская защита + логика формы входа
assets/js/progress.js          — трекер «какие дни уже открывал» (localStorage)
assets/data/marathon-days.js     — контент всех дней марафона (сгенерирован из
                                    материалов бота nutribot, см. ниже)
```

## Цвета и стиль

Палитра взята с референса, который прислала Даша (тёплый кремовый фон +
оранжевый акцент + чёрный). Все цвета собраны в переменные в самом начале
`assets/css/style.css` — чтобы поменять фирменный цвет, достаточно поправить
значения там, а не искать по всему файлу.

## Что нужно доделать вручную

- **Фото Сергея.** Сейчас в hero-блоке и в блоке «Обо мне» стоят
  пунктирные плейсхолдеры — замени их на `<img>` с реальными фото.
- **Контакты в футере.** Telegram и hellodoc.app — настоящие (из брифа).
  WhatsApp и ссылка на Авито помечены жёлтым как `[заполнить]` — впиши
  реальные данные.
- **Отзывы.** Специально не добавлял раздел с отзывами клиентов — чтобы не
  выдумывать несуществующие имена и цифры. Как только будут реальные
  отзывы (с согласия клиентов), можно добавить секцию по образцу
  `.philosophy-grid` или `.feature-card`.

## Как устроен вход в марафон

Это **не настоящая регистрация**, а простая проверка пароля прямо в
браузере (файл `assets/js/auth.js`, переменная `MARATHON_PASSWORD`,
сейчас `marathon30`). Подходит как временное решение, чтобы случайный
посетитель не наткнулся на материалы по прямой ссылке.

Как это работает:
1. Человек вводит пароль на `login.html`.
2. Если пароль верный — в `localStorage` браузера ставится флажок,
   и человека перекидывает в `marathon.html`.
3. `marathon.html` и `day.html` при загрузке проверяют этот флажок
   (`requireAuth()`) и, если его нет, отправляют обратно на `login.html`.

**Ограничения:** пароль лежит в открытом виде в JS-файле — любой, кто
посмотрит исходный код страницы, может его увидеть. Это нормально для
старта, но не подходит для платного закрытого контента на постоянной
основе. Когда будешь готов(а) настроить нормальную регистрацию (с базой
пользователей, оплатой и т.п.) — этот файл нужно будет заменить на
реальную проверку на сервере (например, через любой сервис форм/оплаты
или бэкенд).

Сменить пароль: открой `assets/js/auth.js`, поменяй строку
`const MARATHON_PASSWORD = "marathon30";`.

## Материалы марафона (30 дней)

Даша прислала архив `nutribot` — это отдельный существующий Telegram-бот,
который присылал участникам маршрутный сценарий по дням (текст + фото,
видео-кружки, голосовые, видео, документы), собранный из выгрузки
BotHelp. Я взял оттуда `data/days.json` — реальный контент всех 29 дней
(в исходном сценарии «День 18» отдельно не встречается, поэтому в списке
дней сайта тоже есть такой пропуск) — и сконвертировал его в
`assets/data/marathon-days.js`, чтобы показывать те же материалы на
сайте, а не только в Telegram-боте.

Файлы фото/видео/голосовых **не скопированы на сайт** — ссылки ведут на
хранилище BotHelp (`storage2.bothelp.io`), где они и лежали изначально.
Это означает:
- Ничего никуда не нужно заливать дополнительно — просто открывать сайт.
- Но если BotHelp когда-нибудь удалит эти файлы или сменит ссылки — они
  перестанут открываться и на сайте. Если важно, чтобы марафон работал
  «навсегда» независимо от BotHelp, лучше будет скачать медиафайлы и
  переложить их в `assets/media/`, поправив ссылки в
  `assets/data/marathon-days.js`.

Чтобы поправить текст или заголовок конкретного дня — редактируй
`assets/data/marathon-days.js` напрямую (это обычный JS-файл с массивом
объектов, редактируется как JSON). Если пришлёшь обновлённый набор
данных или новый экспорт из бота — файл можно перегенерировать заново.

«Кнопки» из исходного бота (например, «Задание на сегодня», «Подсчёт
калорий») в оригинале вели в другие ветки бота, которых нет в этой
выгрузке — на сайте они показаны как небольшие плашки-подсказки
🎯 без ссылки, просто чтобы было видно: в этом месте у Сергея было
отдельное задание/материал.

## Деплой на GitHub Pages

1. Создай репозиторий на GitHub, запушь туда содержимое этой папки.
2. В настройках репозитория → **Pages** → Source: ветка `main`, папка `/root`.
3. Через минуту сайт будет доступен по адресу вида
   `https://<твой-логин>.github.io/<репозиторий>/`.

Никакой сборки, Node.js или сервера не нужно — это обычные статические
файлы.
